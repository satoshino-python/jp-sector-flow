# jp-sector-flow

日本株の業種別に、どこへ資金が向かっているかを毎営業日に更新するダッシュボードです。

## 仕組み

- **価格・相対強度**: NEXT FUNDS TOPIX-17業種ETF(1617〜1633)をTOPIX連動ETF(1306)と比較
- **売買代金**: 業種ETFは薄くノイズが大きいため使わず、構成銘柄の売買代金を業種別に合算
- **広がり**: 業種内の25日線上銘柄比率、上昇日の売買代金比率
- **自前の業種指数(主軸)**: 構成銘柄の調整後終値から、時価総額加重(JPX公表のTOPIXウエイトを使用)と均等加重の業種指数を作ります。相対強度・判定・スコアは時価総額加重の指数を全銘柄の同じ指数と比べたものです。業種ETFとTOPIXの比較は参考値として残しています
- **対象銘柄**: JPXが毎月公表するTOPIX構成銘柄のウエイト一覧から自動生成(現在は TOPIX500。全銘柄へ広げる予定)
- データ取得は `yfinance`(非公式)。GitHub Actionsが平日16:37 JST(と、保険の16:57 JST)に差分取得し、BigQuery と `docs/index.html` を更新します

### ETFから個別銘柄への移行(段階的に進行中)

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | 調整後終値を保存し、均等加重の業種指数を作ってETFと比較 | 実装済み |
| 2 | 銘柄リストをJPXのTOPIXウエイトから自動生成(TOPIX500)。分割取得、時価総額加重の業種指数 | 実装済み |
| 3 | TOPIX500で数週間運用して問題なければ全銘柄へ(`daily.yml` の `UNIVERSE_SCOPE` を `all` に) | 運用待ち |
| 4 | 相対強度の主軸を自前の時価総額加重指数へ。ETFとTOPIXの比較・基準価額の突き合わせは参考に格下げ | 実装済み |

### 価格データの保存と取り直し

株価の保存先は BigQuery のテーブル `prices` です。列は終値(`close`、分割調整のみ。売買代金に使用)、調整後終値(`adj_close`、分割+配当調整。リターンに使用)、出来高、売買代金。
毎回の実行では、最初に直近450日分を作業用の `data/prices.parquet` に読み出し(`bq_sync.py --pull`)、差分を取得して足し、最後に書き戻します。parquet はリポジトリにはコミットしません(2026年10月まではコミットしていたため、それ以前の履歴には残っています)。

取得は銘柄を150銘柄ずつに分け、間を数秒空けます。取得できなかった銘柄だけ、小さく分けてもう1回試します。

Yahooは分割や配当があると過去の値まで書き換えるため、直近分だけを継ぎ足すと履歴の途中に偽の急騰・急落ができます。
そこで毎回、取り直した直近7日分と保存済みの値を突き合わせ、0.1%超食い違う銘柄を次のように直します。

- 重複期間の全日で「新/旧」の比がそろっている(配当落ち・株式分割の典型)→ 保存済みの値にその倍率を掛けて直す。分割では出来高も逆向きに直す
- 比がそろっていない(一部の日だけ違う、誤データなど)→ その銘柄だけ全期間を取り直す

倍率での修正は作業用の期間(直近450日)に対して行うので、BigQuery の `prices` にあるそれより古い行は直されません。
それでも日次で±45%を超える動きは誤データとみなして指数の計算から除外し、画面に件数を表示します。
全銘柄を取り直したいときは、手元で `python src/fetch.py --full` を実行してから `python src/bq_sync.py` で反映してください(Google Cloud の認証が必要)。

### 対象銘柄(TOPIX構成銘柄から自動生成)

`src/universe.py` が、JPXのTOPIX構成銘柄別ウエイト一覧(`topixweight_j.csv`、月1回更新)を取得し、`data/universe.csv` を作ります。

- 東証33業種を TOPIX-17 業種に対応付けます(対応表は `universe.py` の `SECTOR33_TO_17`)
- 範囲は環境変数 `UNIVERSE_SCOPE`(`daily.yml` で設定): `topix500`(Core30+Large70+Mid400)/ `all`(TOPIX全銘柄)
- 読み取った一覧は `data/topix_weights.csv` に保存。取得や読み取りに失敗したら、前回の保存分で続行し、ジョブを失敗させて知らせます
- CSVの列は名前の一部(「コード」「業種」「ウエイト」など)で探します。見つからない、銘柄数が想定外、対応表にない業種がある場合は、銘柄リストを書き換えません
- 業種ETFと TOPIX連動ETF(1306)は `data/etfs.csv` の固定リストです
- 新しく対象になった銘柄は、次の実行で全期間(約420日)を取得します

時価総額加重の業種指数は、JPXのウエイト(浮動株調整済み、月末時点)を、株数が変わらないものとして値動きで動かして使います(月の途中・過去の日のウエイトは近似)。

### BigQueryのテーブル

`GCP_SA_KEY`(サービスアカウントのJSON鍵)をGitHubのSecretに登録しておく必要があります。

| テーブル | 内容 |
|---|---|
| `prices` | 株価(日付でパーティション、銘柄コードでクラスタ)。一時テーブルへロード → `MERGE`(キーは date, code)で反映するので、Yahooが過去値を書き換えた場合も上書きされる |
| `universe` | 対象銘柄リスト(毎回全置換。33業種、規模区分、TOPIXウエイトを含む) |
| `sector_summary` | 業種ごとの最新指標(`as_of` × 業種で日ごとに積み上げ) |
| `sector_timeseries` | 直近120営業日の相対強度(ETF・時価総額加重・均等加重)・売買代金シェアの推移(毎回全置換) |

- 書き込みはロードジョブのみ(無料)。ストリーミング挿入は使いません。クエリには `maximum_bytes_billed`(1GB)を付けています
- 列を追加したときは、既存のテーブルに自動で列が足されます(`ensure_tables`)
- 反映後に、送った全行が同じ値で `prices` にあることを確かめ、食い違えばジョブが失敗します
- 手元で内容だけ確認するには `python src/bq_sync.py --dry-run`

### 共有用アーティファクト(スナップショット版)

BigQuery の権限がない人にも見せるための版です。データはページ自体に埋め込まれ、閲覧にBigQueryは要りません。

- `src/snapshot.py` が、その日の計算結果(業種の最新指標、120営業日の推移、業種ごとの売買代金上位30銘柄の60日分)を `data/snapshot.json` に書き出します
- `daily.yml` の最後の工程が、これを孤立ブランチ `snapshot` に1コミットだけ強制pushします(履歴は溜まりません。`main` には入りません)
- `artifact/build.py` が `artifact/snapshot.template.html` にそのJSON(と、任意でClaudeの見立て)を埋め込んで1枚のHTMLを作り、Claudeの定時タスクがアーティファクトとして再公開します
- ページの見た目と操作はリアルタイム版と同じで、「最新を取得」と BigQuery 接続だけがありません

### 実行時刻のずれへの備え

GitHub Actions のスケジュール起動は、混み合う時刻(毎時0分・30分)に数分〜数十分遅れたり、まれに飛ばされたりします。
そのため、混まない分(16:37 JST)にし、20分後の 16:57 JST にもう一度かけています。
2回目の起動では、最初に `gate` ジョブ(`src/gate.py`)が BigQuery の最新の基準日を見て、当日分がすでに入っていれば本体をスキップします(数十秒で終わります)。
手動実行と `trigger/run.txt` のpushでは、常に本体を実行します。当日分の確認に失敗したときも、取りこぼさないよう実行します。
それでも当日分が入らなかったときは、17:15 のClaudeの定時タスクが再実行をかけます。

### 再実行のしかた

Actionsを手動で動かす以外に、`trigger/run.txt` を更新して `main` にpushすると `daily-update` が再実行されます(スケジュールが遅れた・失敗したときに、自動化から再実行するための入口です)。
同じ内容のまま上書きしてもpushされないので、日時と理由を1行書き足してください。実行中に重ねて起動した場合は、前の実行が終わってから順に動きます。

## 主な指標

| 指標 | 意味 |
|---|---|
| 相対強度(時価総額加重、`cw_rel_*`) | 業種内銘柄の時価総額加重指数のリターン − 全銘柄の時価総額加重指数のリターン(%pt)。判定・スコア・順位の主軸 |
| 相対強度(ETF参考、`rel_*`) | 業種ETFのリターン − TOPIX連動ETF(1306)のリターン(%pt)。参考値 |
| 売買代金シェアz | 業種の売買代金シェア(5日平均)が、過去60日の平均からどれだけ離れているか |
| 売買代金 当日/20日 | 当日の業種売買代金 ÷ 直近20日平均(当日除く) |
| 上昇日の売買比率 | 直近5日の売買代金のうち、上昇銘柄の分の割合 |
| 25日線上比率 | 業種内で25日移動平均を上回る銘柄の割合 |
| 判定(`cw_label`) | 時価総額加重の相対強度20日とシェアzの符号で4分類(資金流入/買い細り/売り圧力・転換前/低調) |
| 相対強度(銘柄均等) | 業種内銘柄の均等加重指数のリターン − 全銘柄の均等加重指数のリターン(%pt) |
| 注意(`ew_flag` / `etf_flag`) | 時価総額加重と、均等加重・ETFの相対強度の符号が食い違う業種(±0.3pt未満は無視) |

### 終値と基準価額の突き合わせ

業種ETFは売買代金が薄く、終値が理論値(基準価額)からずれることがあります。
そこで野村アセットが公開する基準価額(分配金再投資)のCSVを毎回取得し、終値ベースの20日騰落との差を確認します。

- 差が0.5ptを超える、または相対強度の符号が食い違う業種に⚠を付けます(閾値は `src/metrics.py` の `DEV_WARN_PT` / `SIGN_EPS`)
- ETFの終値と基準価額の突き合わせは参考情報です。基準価額の取得に失敗した場合は、突き合わせなしで動き続けます
- 基準価額は引け後しばらくして公表される可能性があるため、突き合わせの基準日が終値の最新日より前になることがあります(画面に基準日を表示)
- 基準価額データはリポジトリに保存しません(毎回取得)。データ提供元の利用条件は未確認なので、各自で確認してください

売買代金は買いと売りの合計で、純流入ではありません。価格とセットで読み、外国人投資家の週次売買(JPX公表)などで裏取りしてください。

## セットアップ(初回のみ)

1. **Actionsの書き込み権限**: Settings → Actions → General → Workflow permissions → *Read and write permissions*
2. **Pagesの有効化**: Settings → Pages → Source: *Deploy from a branch* → Branch: `main` / `/docs`
3. **初回実行**: Actions タブ → *daily-update* → *Run workflow*

公開URLは `https://<ユーザー名>.github.io/jp-sector-flow/` です。

## ローカル実行

```bash
pip install -r requirements.txt
python src/fetch.py --demo      # 合成データで動作確認(実データではない)
python src/dashboard.py --demo  # docs/index.html を生成
```

実データで動かすには Google Cloud の認証(`GOOGLE_APPLICATION_CREDENTIALS`)が必要です。

```bash
python src/universe.py          # 銘柄リストを更新
python src/bq_sync.py --pull    # BigQuery から株価を読み出す
python src/fetch.py             # 差分取得
python src/dashboard.py
python src/bq_sync.py           # BigQuery へ反映
```

## 注意

- TOPIX500の段階では、中小型株は集計に入っていません
- 先物・オプションSQ、指数リバランス、決算期は売買代金が歪みます
- GitHub Actionsのcronは遅延することがあります。リポジトリに60日間動きがないとスケジュールが止まる場合があるため、止まっていたら手動実行してください
- 本ツールは投資判断の材料の一つであり、売買の推奨ではありません
