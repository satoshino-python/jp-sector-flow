# jp-sector-flow

日本株の業種別に、どこへ資金が向かっているかを毎営業日に更新するダッシュボードです。

## 仕組み

- **価格・相対強度**: NEXT FUNDS TOPIX-17業種ETF(1617〜1633)をTOPIX連動ETF(1306)と比較
- **売買代金**: 業種ETFは薄くノイズが大きいため使わず、構成銘柄の売買代金を業種別に合算
- **広がり**: 業種内の25日線上銘柄比率、上昇日の売買代金比率
- **自前の業種指数(主軸)**: 構成銘柄の調整後終値から、時価総額加重(JPX公表のTOPIXウエイトを使用)と均等加重の業種指数を作ります。相対強度・判定・スコアは時価総額加重の指数を全銘柄の同じ指数と比べたものです。業種ETFとTOPIXの比較は参考値として残しています
- **対象銘柄**: JPXが毎月公表するTOPIX構成銘柄のウエイト一覧から自動生成(現在は TOPIX500。全銘柄へ広げる予定)
- データ取得は `yfinance`(非公式)。GitHub Actionsが平日16:37 JST(と、保険の16:57 JST)に差分取得し、BigQuery と `docs/index.html` を更新します

### ETFから個別銘柄への移行(段階的に進行中)

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | 調整後終値を保存し、均等加重の業種指数を作ってETFと比較 | 実装済み |
| 2 | 銘柄リストをJPXのTOPIXウエイトから自動生成(TOPIX500)。分割取得、時価総額加重の業種指数 | 実装済み |
| 3 | TOPIX500で数週間運用して問題なければ全銘柄へ(`daily.yml` の `UNIVERSE_SCOPE` を `all` に) | 運用待ち |
| 4 | 相対強度の主軸を自前の時価総額加重指数へ。ETFとTOPIXの比較・基準価額の突き合わせは参考に格下げ | 実装済み |

### 価格データの保存と取り直し

株価の保存先は BigQuery のテーブル `prices` です。列は終値(`close`、分割調整のみ。売買代金に使用)、調整後終値(`adj_close`、分割+配当調整。リターンに使用)、出来高、売買代金。
ローソク足のために、始値・高値・安値(`open`・`high`・`low`。終値と同じく分割調整のみ)も保存します。配当調整後の水準にするには `adj_close / close` を掛けます。
列を足した直後は過去の行に始値などがないため、`fetch.py` が、直近200日の始値が半分超欠けている銘柄を全期間取り直して埋め戻します(初回の実行だけ長くなります。2回目以降は差分のみ)。
毎回の実行では、最初に直近450日分を作業用の `data/prices.parquet` に読み出し(`bq_sync.py --pull`)、差分を取得して足し、最後に書き戻します。parquet はリポジトリにはコミットしません(2026年10月まではコミットしていたため、それ以前の履歴には残っています)。

取得は銘柄を150銘柄ずつに分け、間を数秒空けます。取得できなかった銘柄だけ、小さく分けてもう1回試します。

Yahooは分割や配当があると過去の値まで書き換えるため、直近分だけを継ぎ足すと履歴の途中に偽の急騰・急落ができます。
そこで毎回、取り直した直近7日分と保存済みの値を突き合わせ、0.1%超食い違う銘柄を次のように直します。

- 重複期間の全日で「新/旧」の比がそろっている(配当落ち・株式分割の典型)→ 保存済みの値にその倍率を掛けて直す。分割では出来高も逆向きに直す
- 比がそろっていない(一部の日だけ違う、誤データなど)→ その銘柄だけ全期間を取り直す

倍率での修正は作業用の期間(直近450日)に対して行うので、BigQuery の `prices` にあるそれより古い行は直されません。
それでも日次で±45%を超える動きは誤データとみなして指数の計算から除外し、画面に件数を表示します。
全銘柄を取り直したいときは、手元で `python src/fetch.py --full` を実行してから `python src/bq_sync.py` で反映してください(Google Cloud の認証が必要)。

### 対象銘柄(TOPIX構成銘柄から自動生成)

`src/universe.py` が、JPXのTOPIX構成銘柄別ウエイト一覧(`topixweight_j.csv`、月1回更新)を取得し、`data/universe.csv` を作ります。

- 東証33業種を TOPIX-17 業種に対応付けます(対応表は `universe.py` の `SECTOR33_TO_17`)
- 範囲は環境変数 `UNIVERSE_SCOPE`(`daily.yml` で設定): `topix500`(Core30+Large70+Mid400)/ `all`(TOPIX全銘柄)
- 読み取った一覧は `data/topix_weights.csv` に保存。取得や読み取りに失敗したら、前回の保存分で続行し、ジョブを失敗させて知らせます
- CSVの列は名前の一部(「コード」「業種」「ウエイト」など)で探します。見つからない、銘柄数が想定外、対応表にない業種がある場合は、銘柄リストを書き換えません
- 業種ETFと TOPIX連動ETF(1306)は `data/etfs.csv` の固定リストです
- 新しく対象になった銘柄は、次の実行で全期間(約420日)を取得します

時価総額加重の業種指数は、JPXのウエイト(浮動株調整済み、月末時点)を、株数が変わらないものとして値動きで動かして使います(月の途中・過去の日のウエイトは近似)。

### BigQueryのテーブル

`GCP_SA_KEY`(サービスアカウントのJSON鍵)をGitHubのSecretに登録しておく必要があります。

| テーブル | 内容 |
|---|---|
| `prices` | 株価(日付でパーティション、銘柄コードでクラスタ)。一時テーブルへロード → `MERGE`(キーは date, code)で反映するので、Yahooが過去値を書き換えた場合も上書きされる |
| `universe` | 対象銘柄リスト(毎回全置換。33業種、規模区分、TOPIXウエイトを含む) |
| `sector_summary` | 業種ごとの最新指標(`as_of` × 業種で日ごとに積み上げ) |
| `minervini_screen` | ミネルヴィニのスクリーニング結果(`as_of` × 銘柄で日ごとに積み上げ。ZigZag の転換点や損切り位置を含む) |
| `minervini_backtest` | バックテストの売買と見送り(売買ルール × シグナル。実行のたびに全置換) |
| `sector_timeseries` | 直近120営業日の相対強度(ETF・時価総額加重・均等加重)・売買代金シェアの推移(毎回全置換) |

- 書き込みはロードジョブのみ(無料)。ストリーミング挿入は使いません。クエリには `maximum_bytes_billed`(1GB)を付けています
- 列を追加したときは、既存のテーブルに自動で列が足されます(`ensure_tables`)
- 反映後に、送った全行が同じ値で `prices` にあることを確かめ、食い違えばジョブが失敗します
- 手元で内容だけ確認するには `python src/bq_sync.py --dry-run`

### 共有用アーティファクト(スナップショット版)

BigQuery の権限がない人にも見せるための版です。データはページ自体に埋め込まれ、閲覧にBigQueryは要りません。

- `src/snapshot.py` が、その日の計算結果(業種の最新指標、120営業日の推移、業種ごとの売買代金上位30銘柄の直近180営業日分のローソク足)を `data/snapshot.json` に書き出します
- `daily.yml` の最後の工程が、これを孤立ブランチ `snapshot` に1コミットだけ強制pushします(履歴は溜まりません。`main` には入りません)
- `artifact/build.py` が `artifact/snapshot.template.html` にそのJSON(と、任意でClaudeの見立て)を埋め込んで1枚のHTMLを作り、Claudeの定時タスクがアーティファクトとして再公開します
- ページの見た目と操作はリアルタイム版と同じで、「最新を取得」と BigQuery 接続だけがありません

### 実行時刻のずれへの備え

GitHub Actions のスケジュール起動は、混み合う時刻(毎時0分・30分)に数分〜数十分遅れたり、まれに飛ばされたりします。
そのため、混まない分(16:37 JST)にし、20分後の 16:57 JST にもう一度かけています。
2回目の起動では、最初に `gate` ジョブ(`src/gate.py`)が BigQuery の最新の基準日を見て、当日分がすでに入っていれば本体をスキップします(数十秒で終わります)。
手動実行と `trigger/run.txt` のpushでは、常に本体を実行します。当日分の確認に失敗したときも、取りこぼさないよう実行します。
それでも当日分が入らなかったときは、17:15 のClaudeの定時タスクが再実行をかけます。

### 再実行のしかた

Actionsを手動で動かす以外に、`trigger/run.txt` を更新して `main` にpushすると `daily-update` が再実行されます(スケジュールが遅れた・失敗したときに、自動化から再実行するための入口です)。
同じ内容のまま上書きしてもpushされないので、日時と理由を1行書き足してください。実行中に重ねて起動した場合は、前の実行が終わってから順に動きます。

## 個別銘柄スクリーナー(ミネルヴィニの成長株投資法)

`src/minervini.py` は、ミネルヴィニのトレンドテンプレートで候補を絞り、VCP(ボラティリティ収縮パターン)の買いポイントと、銘柄ごとのボラティリティ(ATR)を加味した損切り位置を出します。
毎営業日 `daily-update` の中で実行し、結果を BigQuery の `minervini_screen` に日付ごとに貯めます(テンプレートを6条件以上満たした銘柄。同じ日の再実行は上書き)。

```bash
python src/minervini.py --bq                      # BigQuery の prices から直接読む(要認証)
python src/minervini.py --bq --as-of 2026-09-01   # 過去のある日時点で判定
python src/minervini.py --bq --equity 5000000     # 資金額から株数(100株単位)も出す
python src/minervini.py --bq --save               # 結果を BigQuery の minervini_screen に保存
```

過去の日付で実行し直すときは、GitHub Actions の *minervini-screen* を判定日を指定して手動実行します(BigQuery に保存されます)。

### データの流れ

```
daily-update(平日夕方)
  bq_sync.py --pull → fetch.py → dashboard.py → bq_sync.py(prices などを BigQuery へ)
  → minervini.py --save(data/prices.parquet から判定し、BigQuery の minervini_screen へ。失敗しても本体は止めない)

検証用ページ(artifact/minervini.html、Claude のアーティファクト)
  → 閲覧している人の Google Cloud BigQuery コネクタで minervini_screen と prices を読んで描く
```

- 判定結果の置き場所は BigQuery の `minervini_screen` だけです(キーは `as_of` × 銘柄、日付で分割)。CSV やチャート用のデータをリポジトリやブランチに置くことはしません
- `minervini_screen` には、テンプレートを6条件以上満たした銘柄の判定、VCP の結果、検出した転換点(`zigzag`。`[種類, 日付, 価格]` の JSON)、ベースの起点、出来高を見た期間、ピボット・損切りなどが入ります
- 検証用ページは、基準日を選んで、テンプレート通過銘柄のチャートに、検出したベース・収縮・ピボット・損切り・2Rを重ねて表示します。データはページに埋め込まず、開くたびに BigQuery から読みます(BigQuery の権限がない人には表示されません)。銘柄ごとに「妥当/要修正/保留」とメモを付け、まとめてコピーできます(ブラウザにだけ保存)
- ページの判定条件の表示用に、しきい値をページ側にも書いています。`src/minervini.py` の定数を変えたら `artifact/minervini.html` の `P` も合わせてください

| 段階 | 内容 |
|---|---|
| トレンドテンプレート | 株価 > 150日線・200日線、150日線 > 200日線、200日線が1か月前より上、50日線 > 150日線・200日線、株価 > 50日線、52週安値から+30%以上、52週高値から-25%以内、RS 70以上。8条件すべてを満たす銘柄が候補 |
| RS(相対力) | 3・6・9・12か月騰落率を 2:1:1:1 で加重し、対象銘柄の中で順位付け(1〜99)。IBDの値の代わり。対象がTOPIX500の間は「TOPIX500の中での相対力」 |
| VCP | 直近約6か月の最高値をベースの起点とし、高値→安値の下落(収縮)を数える(区切り方は下記)。収縮が2〜6回で、最初35%以内・最後10%以内、最後の収縮がベースの中で最も浅く(途中で一度深くなってもよいが、最初の収縮より深いものは不可)最初の半分以下、直近10日の出来高が50日平均の85%以下ならVCP |
| エントリー | ピボット = 最後の収縮の起点の高値。終値が出来高(50日平均の1.4倍以上)を伴って上抜けたら「ブレイク」。ピボットから5%超上は「伸びすぎ(見送り)」。上抜けた日にはテンプレートを満たしておらず、後から満たした銘柄は「ブレイク済み(後追い)」(新しいブレイクではないので買わない) |
| 損切り | 「最後の収縮の安値 − 0.5ATR」と「エントリー − 1.5ATR」の遠い方。値動きの荒い銘柄ほど広くなる。損切り幅が10%を超える銘柄は「リスク過大(見送り)」(損切りを浅くはしない) |
| 資金管理 | 1トレードの損失を資金の1.25%まで、1銘柄は資金の25%までで株数を計算。利益目標の目安2R・3R、含み益が2Rに達したらストップを建値へ(`breakeven_at`) |

しきい値はすべて `src/minervini.py` 冒頭の定数です。業績(EPS・売上の加速)は取得していないため判定に入っていません。候補は決算で別途確かめてください。

### 収縮の区切り方(ZigZag)

高値・安値の区切り(転換点)は、そこから一定の幅(反転幅)以上逆に動いたときに確定します。高値はそこから反転幅以上下げたら、安値はそこから反転幅以上戻したら確定です。

1. ベースの起点から今日までを**粗い反転幅**(5%か ATRの2.5倍の大きい方)で区切る。大きな波だけが残り、その中の小さな揺れは数えない
2. 粗い区切りで**最後に確定した転換点**(「最後の大きな転換点」。高値のことも安値のこともある。一度も確定しなければベースの起点)から今日までだけを、**細かい反転幅**(3%か ATRの1.5倍の大きい方)で区切り直す
3. 1 の転換点までと 2 をつなげる。今日がまだ下げの途中なら、戻りを待たずに今日までの下げを最後の収縮として数える
4. 上昇の途中の押しは取り除く。高値 → 押し → より高い高値 で、押しが前の安値を割っていなければ(安値も高値も切り上げていれば)、上昇の途中の揺れで収縮ではない。押しが前の安値を割っていたら残す

細かく見直すのは、最後のタイトな収縮(3〜4%程度)は粗い反転幅に届かず、戻した後だと粗い区切りでは見えなくなるためです。
例: カネカ(2026-10-14)。粗い区切りでは 8/14 高値 6,458 → 9/11 安値 5,702(9/28 に 6,153 まで戻して確定)で終わり、その後の 3〜4% の押しは見えない。
9/11 から先を細かく区切ると 9/28 高値 6,153 → 10/02 安値 5,937、10/07 高値 6,129 → 10/09 安値 5,944 が見え、収縮は 12% → 4% → 3%、ピボットは 6,129 になる。

起点の日の安値(高値)は使わず、翌日から追います。1日の中で高値と安値のどちらが先かは分からないため、決算などで値幅の大きい日が起点になると、その日の値幅を収縮と数えてしまうためです。

### 判定条件を決めた経緯

チャートで目視確認しながら決めました(基準日 2026-10-14、TOPIX500)。

| 決めたこと | 理由 |
|---|---|
| 収縮は「毎回浅くなる」ではなく「最後がベースの中で最も浅い」で判定 | 毎回浅くなることを求めると、途中で一度深くなっただけの形(カネカなど)を落とす。VCP で大事なのは最後が最もタイトなこと |
| 途中に最初より深い(1割超)収縮があれば不可 | 東京精密(20% → 15% → 25% → …)のように、途中に最初より深い下げがある形は VCP の趣旨に反する |
| 区切りは粗い反転幅と、最後の部分だけ細かい反転幅の2段階 | 反転幅3%だけでは、半年近いベースの小さな揺れまで数え、収縮が10回以上になる銘柄が多かった。粗くするだけでは最後のタイトな収縮を拾えない |
| 起点の日の値幅は収縮に数えない | カネカで、決算日(8/14)の高値→同じ日の安値の8%を最初の収縮と数えていた |
| 上昇の途中の押し(前の安値を割らず、後でより高い高値を付けたもの)は収縮に数えない | カシオ(2026-10-22)。9/25 高値 2,210 → 9/29 安値 2,114.5 の 4.32% の押しが細かい反転幅(ATRの1.5倍)のちょうど境目にあり、ATR が日々わずかに動くだけで数えたり数えなかったりして、1日だけ「最後の収縮が最も浅くない」で外れていた。この押しの後に 10/07 高値 2,315 で抜いているので、上昇途中の揺れとして形で除く。前の安値を割った押しまで除くと、東京精密(2026-10-14)のように安値を切り下げる深い下げが最初の収縮に混ざって 32% → 7% と合格してしまったので、割ったものは残す |

### バックテスト(src/minervini_backtest.py)

スクリーナーと同じ判定関数で、2021〜2025年のシグナルを売買まで再現します。BigQuery の株価を使うので、GitHub Actions の *minervini-backtest* で動かします(手動実行で期間を指定できます。バックテストを変更したブランチへの push でも動きます)。
売買の一覧は BigQuery の `minervini_backtest` に入り(実行のたびに全置換)、検証用ページの「バックテスト」で、各トレードをシグナル・買い・損切り・売りまでチャートで確かめられます。

比べている売買ルール(`VARIANTS`):

| variant | シグナル | 損切り |
|---|---|---|
| `vcp_pivot` | VCP と判定され、終値が出来高を伴ってピボットを初めて上抜けた日 | 最後の収縮の安値 − 0.5ATR(と 終値 − 1.5ATR の遠い方) |
| `vcp_pivot_anyvol` | 上の出来高の条件(50日平均の1.4倍以上)を外したもの。ブレイク日の出来高倍率は `breakout_vol` で見られる | 同上 |
| `high52_8pct` | 終値が前日までの52週高値を初めて上抜けた日(VCP は問わない) | 買値の8%下 |
| `vcp_high52_8pct` | 上の52週高値抜けのうち、その日に VCP と判定されたもの | 買値の8%下 |

- どのルールも、シグナル日にトレンドテンプレートを満たしていることが前提。買いは翌営業日の始値、+2R に達したら翌日から損切りを買値へ上げ、終値が50日線を割ったら翌営業日の始値で売る
- 翌日の始値がピボット(52週高値)の5%超上なら「伸びすぎ」、損切り幅が10%超なら「リスク過大」、その銘柄を保有中なら見送る
- 成績は R(買値 − 当初の損切り)の倍数で見る。ログに、ルールごと・年ごとの勝率、平均R、ペイオフレシオ(勝ちの平均 ÷ 負けの平均)、PF、手仕舞いの理由、見送りの内訳を出す

注意: 対象は現在の TOPIX500(過去に除外・上場廃止された銘柄を含まないので成績は良く出やすい)。手数料・スリッページなし。1トレードずつの成績で、同時に持てる銘柄数(資金の制約)は考えていない(52週高値抜けは平均で数十銘柄を同時に持つ計算になる)。

### 売買シミュレーション(artifact/minervini_sim.html)

「ブレイク」と判定された銘柄を、ルールどおりに売買していたら資産がどうなったかを計算する Claude のアーティファクトです。検証用ページと同じく、開くたびに閲覧している人の BigQuery コネクタでデータを読みます。

- 売買するシグナルは2種類から選べます
  - 日々のスクリーニングの「ブレイク」: `minervini_screen` で状態が「ブレイク」(ブレイク当日)の銘柄。株価(`prices`)を使って、このページの中で売買を再現します(手順はバックテストと同じ)。判定が保存され始めた日からの、実際の判定どおりの記録です。翌営業日の分がまだない銘柄は「注文中」、保有中の銘柄は今の損切り(建値へ上げたか)と含み損益を表示します
  - バックテストのシグナル: `minervini_backtest` の売買をそのまま使い、資金の制約だけを加えます
- 元手・1回の損失の上限(初期値 1.25%)・1銘柄の上限(初期値 25%)・手数料と滑り(片道)・開始日を変えられます
- 株数は「損切りになったときの損失が上限以内」と「1銘柄の上限以内」の少ない方を100株単位に切り捨て。資金は前日の終値で評価した資産で、現金が足りなければ見送ります(信用取引はしない)。同じ日のシグナルは RS の高い順に買います。50日線割れの売りは始値なので、その現金で同じ日に買えます
- 資産の推移、同じ元手で TOPIX 連動ETF(1306)を持った場合、高値からの下落率、年別の成績、売買と見送りの一覧を表示します
- 注意: 計算は調整後の株価で行うため、分割前の時期の1単元の代金は実際と異なります。配当は入れていません。バックテストのシグナルを使う場合の生存者バイアスはバックテストと同じです

## 主な指標

| 指標 | 意味 |
|---|---|
| 相対強度(時価総額加重、`cw_rel_*`) | 業種内銘柄の時価総額加重指数のリターン − 全銘柄の時価総額加重指数のリターン(%pt)。判定・スコア・順位の主軸 |
| 相対強度(ETF参考、`rel_*`) | 業種ETFのリターン − TOPIX連動ETF(1306)のリターン(%pt)。参考値 |
| 売買代金シェアz | 業種の売買代金シェア(5日平均)が、過去60日の平均からどれだけ離れているか |
| 売買代金 当日/20日 | 当日の業種売買代金 ÷ 直近20日平均(当日除く) |
| 上昇日の売買比率 | 直近5日の売買代金のうち、上昇銘柄の分の割合 |
| 25日線上比率 | 業種内で25日移動平均を上回る銘柄の割合 |
| 判定(`cw_label`) | 時価総額加重の相対強度20日とシェアzの符号で4分類(資金流入/買い細り/売り圧力・転換前/低調) |
| 相対強度(銘柄均等) | 業種内銘柄の均等加重指数のリターン − 全銘柄の均等加重指数のリターン(%pt) |
| 注意(`ew_flag` / `etf_flag`) | 時価総額加重と、均等加重・ETFの相対強度の符号が食い違う業種(±0.3pt未満は無視) |

### 終値と基準価額の突き合わせ

業種ETFは売買代金が薄く、終値が理論値(基準価額)からずれることがあります。
そこで野村アセットが公開する基準価額(分配金再投資)のCSVを毎回取得し、終値ベースの20日騰落との差を確認します。

- 差が0.5ptを超える、または相対強度の符号が食い違う業種に⚠を付けます(閾値は `src/metrics.py` の `DEV_WARN_PT` / `SIGN_EPS`)
- ETFの終値と基準価額の突き合わせは参考情報です。基準価額の取得に失敗した場合は、突き合わせなしで動き続けます
- 基準価額は引け後しばらくして公表される可能性があるため、突き合わせの基準日が終値の最新日より前になることがあります(画面に基準日を表示)
- 基準価額データはリポジトリに保存しません(毎回取得)。データ提供元の利用条件は未確認なので、各自で確認してください

売買代金は買いと売りの合計で、純流入ではありません。価格とセットで読み、外国人投資家の週次売買(JPX公表)などで裏取りしてください。
